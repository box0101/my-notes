# HTTP状态码

### 状态码类别

| 状态码 |                         |            描述            |
| :----: | :---------------------: | :------------------------: |
|  1xx   | Informational 信息响应  |     接受的请求正在处理     |
|  2xx   |    Success 成功响应     |      请求正确处理完毕      |
|  3xx   |   Redirection 重定向    | 需要进行附加操作以完成请求 |
|  4xx   | Client Error 客户端错误 |     服务器无法处理请求     |
|  5xx   | Serve Error 服务端错误  |     服务器处理请求出错     |

### 常见状态码

1. **2xx**

**（1）200 OK**

表示客户端发来的请求被服务端正确处理了。

**（2）204 No Content**

表示客户端发来的请求被服务端正确处理了但没有返回的内容。常见于前端发送 DELETE 请求删除某个资源或 PUT 更新数据后不需要返回新数据的情况。

**（3）206 Partial Content**

部分内容响应，表示客户端进行了范围请求。客户端通过 `Range` 请求头指定需要的字节范围，服务端通过 `Content-Range` 响应头告知实际返回的数据范围。

2. **3xx**

**（1）301 Moved Permanently**

**永久重定向。**表示请求的资源被分配了新的 URL，以后应使用资源指定的 URL。新的 URL 在响应头的 `Location` 字段指定，如果用户把旧的 URL 保存为书签，那么会按新的 URL 重新保存书签，同时搜索引擎在抓取内容时也把旧的网址替换为重定位后的网址。

**（2）302 Found**

**临时重定向。**与 301 相似只不过这是临时的，不会将新的 URL 保存为书签而是保留旧网页的URL，同样搜索引擎抓取新内容但不会把旧网址替换成新网址。

**（3）304 Not Modified**

**浏览器缓存**相关，表示协商缓存命中。状态码 304 告诉客户端缓存没有被修改可以直接使用缓存中的资源，所以 304 状态码返回时响应报文的响应体是没有内容的。

**（4）307 Temporary Redirect**

也是临时重定向，和 302 的区别是 302 可以从 POST 变成 GET（尽管302标准禁止这样做），而 307 不会从 POST 变成 GET。

3. **4xx**

**（1）400 Bad Request**

错误请求。表示请求报文中存在语法错误，需要修改请求后再次发送。

**（2）401 Unauthorized**

未授权。表示请求需要用户有通过 HTTP 认证的认证信息。若之前已进行过一次请求则表示用户认证失败。通常是未登录，或者是 Token 缺失/过期。

返回含有 401 状态码的响应头必须包含 `WWW-Authenticate` 字段用于向客户端发起认证请求。

**（3）403 Forbidden**

禁止访问。表示客户端的请求被服务器拒绝了（没有权限访问资源）。和 401 不同的是 403 知道用户身份，明确拒绝访问。

**（4）404 Not Found**

表示访问的资源不存在，服务器无法找到请求的资源。

**（5）405 Method Not Allowed**

表示客户端请求的方法能够被识别但服务端不允许使用该方法。

4. **5xx**

**（1）500 Internal Serve Error**

表示服务器在执行请求时发生了错误。非常笼统的报错，通常是后端代码抛出了异常（如空指针、语法错误等），导致服务器崩溃无法完成请求。

**（2）501Not Implemented**

表示服务器不支持请求中的某个功能。与 405 不同的是 405 表示能够识别该方法但禁用，501是指服务器不支持这个方法。

**（3）502 Bad Gateway**

<u>网关</u>错误。通常发生在反向代理服务器（如 Nginx）上。Nginx 作为网关，将请求转发给后端的真实服务（如 Node.js / Java / Python），但后端服务挂了或者返回了不符合协议的无效响应。

[^网关]: HTTP 层面通常指客户端和服务端之间的一层中间节点。

**（4）503 Service Unavailable**

表示服务器暂时处于超负荷或正在停机维护。

**（5）504 Gateway Timeout**

网关超时。同样多发生在 Nginx 等代理服务器上。网关把请求转发给后端服务，但后端服务处理太慢（可能在死循环或等待数据库锁），网关等不及了，就会返回 504。
