# Vue2 VS Vue3

核心区别可以总结为：**更好的性能、更优的开发体验、更强的逻辑复用能力以及更符合 TypeScript 的类型系统支持。**



## 组合式 API vs 选项式 API

参考官方解释 https://cn.vuejs.org/guide/extras/composition-api-faq.html

### 什么是组合式 API？

组合式 API (Composition API) 是一系列 API 的集合，使我们可以使用函数而不是声明选项的方式书写 Vue 组件。它是一个概括性的术语，涵盖了以下方面的 API：

- 响应式 API：例如 `ref()` 和 `reactive()`，使我们可以直接创建响应式状态、计算属性和侦听器。
- 生命周期钩子：例如 `onMounted()` 和 `onUnmounted()`，使我们可以在组件各个生命周期阶段添加逻辑。
- 依赖注入：例如 `provide()` 和 `inject()`，使我们可以在使用响应式 API 时，利用 Vue 的依赖注入系统。



### 组合式 API 的优势？

1. **更好的逻辑复用**

   可以通过组合函数来实现更加简洁高效的逻辑复用。

2. **更灵活的代码组织**

   组合式 API 中与同一个逻辑关注点相关的代码被归为了一组：无需再为了一个逻辑关注点在不同的选项块间来回滚动切换。此外，组合式 API 可以很轻松地将这一组代码移动到一个外部文件中，不再需要为了抽象而重新组织代码，大大降低了重构成本。

3. **更好的类型推导**

   组合式 API 主要利用基本的变量和函数，它们本身就是类型友好的。用组合式 API 重写的代码可以享受到完整的类型推导，不需要书写太多类型标注。

4. **更小的生产包体积**

   搭配 `<script setup>` 使用组合式 API 比等价情况下的选项式 API 更高效，对代码压缩也更友好。这是由于 `<script setup>` 形式书写的组件模板被编译为了一个内联函数，和 `<script setup>` 中的代码位于同一作用域。不像选项式 API 需要依赖 `this` 上下文对象访问属性，被编译的模板可以直接访问 `<script setup>` 中定义的变量，无需从实例中代理。这对代码压缩更友好，因为本地变量的名字可以被压缩，但对象的属性名则不能。



## 总结

1. Vue2 基于选项式 API，当功能复杂时同一个功能的代码会被分散在不同选项中，不利于维护和复用，Vue3 基于组合式 API，可以按逻辑功能组织代码，极大提高代码复用性和可读性。
2. 响应式系统不同，Vue2 使用 `Object.defineProperty` 对变量的每个属性进行监听，无法监听到属性的增删以及数组下标的修改，Vue3 采用 Proxy 对变量进行全局代理性能更好。
3. 由于 API 的改变，Vue3 基于组合式 API 对 TypeScript 原生支持，Vue2 对 TypeScript 支持较弱。
4. Vue3 模块化更彻底，支持 **Tree-shaking**，没有用到的 API 不会打包进最终产物，因此体积更小。
