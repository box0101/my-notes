# Vue响应式

**官方定义**

Vue 最标志性的功能就是其低侵入性的响应式系统。组件状态都是由响应式的 JavaScript 对象组成的。当更改它们时，视图会随即自动更新，这让状态管理更加简单直观。



#### 响应式原理

无论是 Vue2 还是 Vue3，响应式原理都是**数据劫持**+**订阅-发布**模式的结合：

1. 数据劫持：拦截对象属性的读取（get）和修改（set）操作。
2. 依赖收集（订阅）：在读取数据时将正在执行的副作用函数记录下来，与数据建立联系。
3. 派发更新（发布）：在修改数据时将收集到的副作用函数重新执行触发视图更新。



#### **Vue2和Vue3响应式区别**

二者核心区别在于API的不同，Vue2的响应式系统依赖于ES5的`Object.defineProperty()`方法，而Vue则采用了`Proxy`全局代理。

Vue2的`defineProperty`存在局限：

1. 添加或删除对象属性时监测不到。
2. 无法监控到数组下标和长度的变化。

而Vue3采用Proxy代理整个对象，能够拦截到对对象属性的添加删除操作以及数组长度的变化。



##### Vue3 响应式比 Vue2 更快的原因：

1. **核心 API 不同：**Vue3 使用 Proxy 代理整个对象而不是属性，属性的新增/删除、数组索引修改、长度修改等变化都能被拦截，而 Vue2 基于 `Object.defineProperty` 劫持对象属性，无法监听到属性的新增和删除，对于数组则需要劫持重写数组的方法来实现响应式。
2. **初始化逻辑不同：**Vue2 中实例化一个组件时响应式系统会递归遍历对象的所有层级结构，而 Vue3 的 Proxy 特性只在第一层进行代理，只有深层对象在被访问到（触发 getter）时才会为其生成完整的 Proxy 对象。所以 Vue3 的按需代理策略大大提高了性能。
3. **依赖收集不同：**Vue3 在依赖收集系统的底层使用了 `WeakMap`、Map 和 Set，其中 WeakMap 的键是目标对象，如果这个对象被销毁垃圾回收机制会自动回收，避免了内存泄漏。而 Vue2 大量使用数组来维护依赖，对比之下 Vue3 的查询和内存管理效率更高。

#### 数据双向绑定

数据双向绑定实现了数据与视图的同步，当数据改变时视图会自动更新，在页面输入/交互时也会自动更新对应数据。

数据双向绑定是基于**响应式系统**+**数据劫持**+**发布-订阅者模式**实现的。通过`Object.defineProperty`劫持各个属性的`getter`、`setter`，在数据变动时将消息发布给订阅者。触发相应回调。

具体步骤：

- **observe数据劫持：**递归遍历data对象每个属性，对每个属性使用`Object.defineProperty(obj, key, { get(){...}, set(newVal){...} })`：
  - `get`：当渲染器或某个watcher访问这个属性时就会把属性注册到对应的订阅器Dep里。
  - `set`：当属性赋新值时触发，通知Dep去调用所有Watcher的`Update()`从而触发DOM更新或回调。
- **compile编译解析：**解析模板指令，将模板中的变量（如模板字符串）替换成数据，然后初始化渲染页面视图，并将每个节点绑定更新函数，添加监听数据的订阅者，一旦数据有变动，收到通知更新视图。
- **watcher订阅者：**连接observe和compile的桥梁。watcher在自身实例化时往dep添加自己，并且watcher有一个`update()`方法，当属性变动时会通过`dep.notice()`通知watcher调用`update()`方法触发compile中的回调更新视图。
- **MVVM：**连接上述三者。

Vue中常用v-model语法糖（`:value` + `@input`）实现数据双向绑定，compile会监听input表单的`input`事件，在事件回调里更新数据。

**总结**

observe**数据劫持**遍历`data`对象中的所有属性，通过`Object.defineProperty()`为每个属性设置`getter`、`setter`。当渲染器或watcher访问到属性时就会触发`getter`把这个属性记录在依赖表Dep中，即**收集依赖**。当数据更新时会触发`setter`，它会通知（`notify`）`watcher`的`update()`**更新视图**。同样视图更新时也会触发`setter`**更新数据**。

Vue2和Vue3的区别就在于Vue3不采用`Object.defineProperty()`劫持数据，而是用`Proxy`代理整个对象，用`Proxy`的`get/set`处理器拦截对象操作。



#### 响应式变量

`ref`和`reactive`是当下最常见两种声明响应式变量的方法，二者核心区别在于 ref 是通过**包装对象**实现响应式，而 reactive 是通过 **Proxy 代理**原始对象。

1. **数据类型支持不同**

   - ref 可以接收基本数据类型和引用数据类型，对于基本数据类型，ref 会将其包装成一个有 value 属性的对象。
   - reactive 只能接受引用数据类型，直接通过 Proxy 劫持对象。

2. **访问方式不同**

   ref 声明的响应式变量必须通过 .value 属性访问，reactive 声明的响应式变量可以直接访问。

3. 使用上 ref 在模版里自动解包无需再通过 .value 访问，reactive 有解构丢失响应式的风险，想解决此问题可以用 `toRef` 来解包。
