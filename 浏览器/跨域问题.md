# 跨域问题

跨域问题其实就是浏览器的**同源策略**造成的。

#### **什么是同源策略：**

协议（protocol）、域名（domain）、端口（port）三者必须一致。

**同源策略主要限制了三方面：**

- 当前域下的 js 脚本不能够访问其他域下的 cookie、localStorage 和 indexedDB。

  [^indexedDB]: 是浏览器提供的一种**本地数据库存储机制**，专门用来在用户端存储大量结构化数据。它比 `localStorage` 更强大，因为它可以存储 **对象、二进制数据（Blob、ArrayBuffer）**，而且**容量大很多**，适合离线应用或大型数据缓存。

- 当前域下的 js 脚本不能够访问操作其他域下的 DOM。

- 当前域下 ajax 无法发送跨域请求。



#### 如何解决跨域问题

1. **CORS（跨域资源共享）**

   **官方定义**

   CORS 是一种机制，它使用额外的 HTTP 头来告诉浏览器  让运行在一个 origin (domain)上的Web应用被准许访问来自不同源服务器上的指定的资源。当一个资源从与该资源本身所在的服务器不同的域、协议或端口请求一个资源时，资源会发起一个跨域 HTTP 请求。

   

   CORS 需要服务器和浏览器同时支持，实现CORS的关键是服务器，只要服务器实现了CORS请求就可以跨域通信了。

   浏览器将 CORS 分为**简单请求**和**非简单请求**：

   **（1）简单请求：**

   简单请求不会触发CORS预检请求，若请求满足以下条件则为简单请求：

   ①请求方法是 **HEAD /GET /POST **三者之一。

   ②HTTP头信息不超过以下几种字段：

   - Accept
   - Accept-Language
   - Content-Language
   - Last-Event-ID
   - Content-type

   **请求过程：**

   浏览器会直接发出CORS请求，会在请求头中新增`Origin`字段，该字段用于说明本次请求来自哪个源，服务器则根据这个值决定是否同意这次请求。如果`Origin`指定的域名在许可范围内则服务器返回的响应会多出以下字段：

   ```js
   Access-Control-Allow-Origin: http://api.bob.com  // 和Origin一致
   Access-Control-Allow-Credentials: true   // 表示是否允许发送Cookie
   Access-Control-Expose-Headers: FooBar   // 指定返回其他字段的值
   Content-Type: text/html; charset=utf-8   // 表示文档类型
   ```

   在简单请求中，在服务器内，至少需要设置字段：`Access-Control-Allow-Origin`表示请求成功。

   **（2）非简单请求**

   非简单请求的CORS请求会在正式通信之前进行一次HTTP查询请求，**称为预检请求**。

   浏览器会询问服务器当前网页是否在服务器允许的访问范围内，以及可以使用哪些HTTP请求方式和头信息字段。

   预检请求使用的**请求方法是OPTIONS**，表示这个请求是来询问的。他的头信息中的关键字段是`Origin`，表示请求来自哪个源。除此之外，头信息中还包括两个字段：

   - **Access-Control-Request-Method**：该字段是必须的，用来列出浏览器的CORS请求会用到哪些HTTP方法。
   - **Access-Control-Request-Headers**： 该字段是一个逗号分隔的字符串，指定浏览器CORS请求会额外发送的头信息字段。

   服务器在收到浏览器的预检请求之后，会根据头信息的三个字段来进行判断。如果返回的头信息在中有`Access-Control-Allow-Origin`这个字段就是允许跨域请求，如果没有，就是不同意这个预检请求，就会报错。

   预检通过后浏览器会向服务器发送真正的请求，且每次的CORS请求都会自带一个`Origin`字段，服务器判断允许跨域通信则返回带`Access-Control-Allow-Origin`的响应。

   

2. **JSONP**

   核心原理是利用 **`<script>`** 标签没有跨域限制，浏览器同源策略限制了 Ajax 请求跨域资源，但并不限制 `<script>` 标签加载跨域资源。

   通过 `<script>` 标签 src 属性，发送带有 callback 参数的 GET 请求，服务端将接口返回数据拼凑到 callback 函数中，返回给浏览器，浏览器解析执行，从而前端拿到 callback 函数返回的数据。

   原生JS实现：

   ```js
   <script>
       var script = document.createElement('script');
       script.type = 'text/javascript';
       // 传参一个回调函数名给后端，方便后端返回时执行这个在前端定义的回调函数
       script.src = 'http://www.domain2.com:8080/login?user=admin&callback=handleCallback';
       document.head.appendChild(script);
       // 回调执行函数
       function handleCallback(res) {
           alert(JSON.stringify(res));
       }
    </script>
   ```

   **缺点：**

   - 仅支持GET方法，因为`<script src="...">` 本质上就是 GET 请求。
   - 安全性较差，容易受到XSS攻击。

   

3. **`postMessage`跨域**

   用于解决浏览器窗口与窗口之间的跨域问题。

   `postMessage(data,origin)`方法接受两个参数：

   - **data**： html5规范支持任意基本类型或可复制的对象，但部分浏览器只支持字符串，所以传参时最好用`JSON.stringify()`序列化。
   - **origin**： 协议+主机+端口号，也可以设置为"*"，表示可以传递给任意窗口，如果要指定和当前窗口同源的话设置为"/"。

   接收方：`window.addEventListener('message', callback)`，注意必须在回调函数中必须验证 `origin`。

   

4. **`Nginx`代理（生产环境）**

   通过 Nginx 配置一个中间层，让前端请求同源的路径，由服务器内部转发给真正的后端。

   

5. **Proxy 代理（开发环境）**

   在 Vue 和 React 开发环境中脚手架内置了开发服务器代理，但这仅限开发环境，上线无效。

   

6. **WebSocket**

   WebSocket 本质上绕过了浏览器的同源策略限制，浏览器不拦截，是否跨域完全取决于服务器对 Origin 请求头的校验。
