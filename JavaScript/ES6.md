# ES6

ES6是JavaScript的第六个版本，也称为ES2015。



#### ES6新特性

- **let 和 const 声明变量：**ES6 引⼊了⽤于声明变量的新关键字 let 和 const，解决了使⽤ var 时出现的⼀些不合理的问题，如变量提升、重复声明等。

- **模板字符串**和**解构赋值**

- **扩展运算符：**`...`，用于对象/数组的所有可遍历属性。可用于将数组转换为参数序列、合并对象/数组、浅拷贝等等。

- **箭头函数**

- **Promise对象：**Promise 是⼀种异步编程的解决⽅案，⽐回调函数更加强⼤。与 Promise 相关的还有 Generator和 async。

- **函数参数默认值：**允许函数声明时为参数指定一个默认值，例如

  ```javascript
  function hello(name = 'GEM') { 
      console.log('hello', name)
  }
  ```

- **对象字面量增强：** ES6 引入的一组语法糖，例如属性简写（变量名和对象属性名相同，可以省略冒号和值）、方法简写（定义对象方法时可以省略 `function` 关键字）等。

- **Set 和 Map 数据结构**：Set去重集合，Map支持任意类型的键。

- **Symbol 数据类型：**常用于创建对象的私有或不冲突的键。

- **for...of 循环：**用来遍历可迭代对象。相比 `for…in`，`for…of` 遍历的是**值**而不是索引。

- **模块化：**是 JavaScript 官方在 ES6 中引入的一套模块机制，用来替代之前的 CommonJS 和 AMD 模块规范。它的核心是“静态导入/导出”，语法清晰，依赖关系在编译阶段就能确定，有利于优化和静态分析。

**异步函数`async/await`** 不是 ES6 新特性，是 ES8 引入的新特性。



### 面试常考题

#### let、const、var区别

1. **块级作用域：**let 和 const 具有块级作用域而 var 没有，这其实也跟 var 的**变量提升**有关，用 var 声明变量时会自动将变量提升至当前作用域顶部。

   [^块级作用域]: 块级作用域解决了内层变量可能覆盖外层变量，以及用来计数的循环变量泄露为全局变量的问题。

2. **重复声明：**var 可以重复声明同一个变量，后一个值覆盖前一个值，如果 let 和 const 重复声明同一个变量会直接报错。

3. **暂时性死区：**在使用let、const命令声明变量之前该变量都是不可用的，这在语法上成为暂时性死区。而var则不存在暂时性死区。

   使用“暂时性”一词是因为这个区域取决于代码执行的时间点，而不是代码编写的顺序。例如，下面的代码能够运行，是因为虽然使用 `let` 变量的函数写在变量声明之前，但函数是在暂时性死区外面被*调用*的。
   
   ```javascript
   {
     // 此时进入块级作用域，变量 a 的 TDZ（死区时间）开始！
     
     // 物理位置：位于 let a 声明之前
     const sayHi = function() {
       console.log(a); 
     };
   
     // 引擎执行到这里，a 被初始化，TDZ（死区时间）结束！
     let a = "前端实习"; 
   
     // 调用函数：此时的时间点，已经过了死区结束的时间点。
     sayHi(); // ✅ 完美运行，成功打印 "前端实习"
   }
   ```

这里值得注意的是，JavaScript中的**提升**是指解释器在执行代码之前，似乎将函数、变量、类或导入的*声明*移动到其作用域的顶部的过程。而提升并不是一个普遍认同的术语，所以大多人认为 `let`、`const` 是不提升的。但其实一下任何行为都可以被视为提升：

- 能够在声明变量之前在其作用域中使用该变量的值。（“值提升”）
- 能够在声明变量之前在其作用域中引用该变量而不抛出 `ReferenceError`，但值始终是 `undefined`。（“声明提升”）
- 变量的声明导致在声明行之前的作用域中行为发生变化。
- 声明的副作用在评估包含该声明的其余代码之前产生。

var属于第二种提升，而let、const则属于第三种提升。如果 let 和 const 没有提升那么下面的代码中内部的 value 应该可以顺着作用域链找到外部的 value，但事实是会抛出 ReferenceError 错误，这就是因为上面说的“导致在声明行之前的作用域中行为发生变化”。

```javascript
let value = "外层的值";

{
  console.log(value); 
  let value = "内层的值"; 
}
```

在编译阶段引擎就识别到块级作用域内有 value 这个变量，它会屏蔽掉外部的同名变量，而无法使用的原因就是 let 和 const 不同于 var，虽然提升了变量但是没有给其初始化为 undefined，所以在执行到声明语句之前这个变量都处于**暂时性死区**。

4. **初始值设置：**var和let声明变量可以不赋值，const声明变量必须有初始值。
5. **指针指向（重新赋值）：**const声明的变量不允许重新赋值。



#### 对`async/await`的理解

字面上看，`async`时“异步”的简写，用于声明一个函数是异步函数，它保证函数返回一个 `Promise`，而`await`则表示等待，等待一个 Promise 的完成并暂停当前 `async` 函数的执行，直到 Promise resolved 或 rejected。语法上强制规定`await`只能出现在`async`函数中。

#### ESM 和 CommonJS 的区别

ES Modules（ESM）和 CommonJS（CJS）是前端和 Node.js 生态中最核心的两种模块化规范。ESM 是 ES6 中提出的新特性。

它们不仅在语法上不同，其背后的**加载机制、内存模型以及编译行为**有着本质的区别。这两种规范的差异直接决定了现代化构建工具能否进行代码优化，特别是 **Tree-shaking**。

1. **静态和动态**
   - ESM（静态）：模块依赖关系的构建发生在编译阶段，在代码真正执行前引擎就已经知道了所有的依赖关系。
   - CommonJS（动态）：依赖关系只能在运行时确定。
2. **语法不同**
   - ESM 的 `import/export` 语句必须放在模块的顶层，不能放在 if 语句、函数或循环中。
   - CommonJS 的 `require()` 是一个普通函数，可以在代码任何地方调用，依赖路径可以是动态的字符串拼接。
3. **值引用 vs 值拷贝**
   - ESM（动态只读引用）：ESM 导出的不是值的拷贝而是对内存地址的引用。当导出模块内部修改了变量，导入模块中对应的值会同步更新。如果导入的值是只读的，强行修改会报错。
   - CommonJS（值的浅拷贝）：`module.exports` 导出的是一个对象，`require` 拿到的是对象的浅拷贝。一旦模块被加载并导出，如果原模块内部改变了基本数据类型的值，导入方不会感知到变化（除非导出的是对象引用且修改了对象属性）。
4. **加载方式：异步 vs 同步**
   - ESM 支持异步加载，更适合浏览器环境，引擎分为解析、实例化、求值三个阶段。
   - CommonJS 同步加载模块，因为最初是为 Node.js 设计的，模块都存在本地硬盘，同步加载不会阻塞进程。

ES Modules 代表了前端的未来，它的**静态编译特性**不仅规范了模块化开发，更为 **Tree-shaking** 这种极致的性能优化手段提供了可能；而 CommonJS 虽然在 Node.js 时代立下汗马功劳，但由于其**运行时加载**的动态包袱，在追求极致客户端加载性能的今天，正逐渐被 ESM 替代。
