# JavaScript 底层机制

### 一、作用域和提升

#### **官方定义**

作用域是当前的**执行上下文**，在其中的值和表达式“可见”（可被访问）。如果一个参数或表达式不在当前作用域内是不可用的。作用域也可以堆叠成层次结构，子作用域可以访问父作用域内的变量，反之则不行。

**JavaScript 的作用域**包括：

- 全局作用域：脚本模式运行所有代码的默认作用域
- 模块作用域：模块模式中运行代码的作用域
- 函数作用域：由函数创建的作用域

还有一个额外的作用域，块级作用域：用一对花括号创建出来的作用域。



##### 执行上下文

JavaScript 的执行需要两个软件的配合：JavaScript 引擎和宿主环境。简单来说，执行上下文就是 JavaScript 代码被解析和执行时所在的“环境”。

一个执行上下文的生命周期分为两个阶段：**创建阶段（编译）**和**执行阶段**。

1. **创建阶段**

   当函数被调用但还没开始执行内部代码时引擎会做准备工作，此时上下文内部会包含三个核心组件：

   （1）**词法环境**：用来登记函数声明和 let/const 声明的变量，还包含了一个指向外部环境的引用，这就是作用域链的底层实现原理。

   （2）**变量环境**：其实也是一个词法环境，但它专属于登记 var 声明的变量，同时这些变量被提前赋值为 undefined。

   （3）**决定 this 的绑定**：确定当前上下文中的 this 指向谁。

2. **执行阶段**

   按顺序从上到下执行代码。

常说的闭包本质上就是一个函数执行完它的执行上下文已经弹出调用栈，但由于它的内部函数仍然保持着对它的词法环境的引用，导致这部分内存没有被垃圾回收机制销毁。



#### 词法作用域

上面说的“JavaScript 的作用域”其实就是词法作用域（静态作用域），与之相对的是动态作用域。

词法作用域的核心思想是作用域是由**函数声明的位置**决定的，而动态作用域则认为作用域是由函数被调用的位置决定的。看以下代码就能理解二者区别：

```javascript
let value = 1;

function foo() {
    console.log(value);
}

function boo() {
    let value = 2;
    foo();
}

boo();
```

如果是词法作用域，会输出 1。因为一旦调用 `foo()` 函数时找不到 `value`，就会去它被声明的作用域，即全局作用域里面找。

如果是动态作用域，会输出 2。当调用 `foo()` 函数找不到 `value` 时会去 `foo()` 被调用的作用域内找。



#### 作用域链

作用域链是 JavaScript 引擎在执行代码时，查找变量的一套链式路径。

简单来说，当在代码中使用一个变量时，JavaScript 会先在当前作用域中查找。如果找不到，它就会向上级作用域查找，直到找到该变量或到达全局作用域为止。这种由多个执行环境逐级建立起来的变量查找机制，就是“作用域链”。

作用域链的形成是由 **词法环境** 的嵌套结构决定的。词法环境中有一个指向外部环境的引用，就是通过这个引用将各个词法环境串联了起来。



#### 变量提升和函数提升

##### **提升**

JavaScript 提升是指解释器在执行代码之前，似乎将函数、变量、类或导入的声明移动到其作用域的顶部的过程。

##### 变量提升

在讲 var 和 let/const 区别的时候提到了提升的概念，而变量提升狭义上是特指 var 声明变量时发生的声明提升。

##### 函数提升

函数提升比变量提升更彻底，可以在函数被声明之前调用函数并且能正常执行。

底层原理：在执行上下文的创建阶段，引擎遇到函数声明时会直接在内存中创建改函数对象，并将函数名指向该对象，也就是说函数体也被提升了。



### 二、闭包

**官方定义：**函数和对其周围状态（词法环境）的引用捆绑在一起构成闭包。

闭包是指有权访问另一个函数作用域中变量的函数。常见形式是在一个函数内返回另一个函数，其中访问了外层函数的局部变量。

##### 核心作用

- 数据私有化：闭包可以让变量“外部访问不到但内部能访问”。通常用于创建私有变量，避免全局污染。
- 延长生命周期：闭包会让外部函数的词法环境被内部函数持有引用，因此即使函数执行结束，该环境也不会被垃圾回收，从而实现变量的持续存在。常用于状态保持（防抖节流、函数柯里化）。



##### 内存泄漏与解决

正式因为闭包会让外部函数的词法环境被内部函数持有引用而不被垃圾回收机制回收，如果这些变量不再使用，也就可能导致内存泄漏。

解决办法：及时释放引用、避免无用变量被捕获、解绑事件、控制缓存大小，以及在必要时使用 `WeakMap` 等弱引用结构。



### 三、this 指向

##### 1. 普通函数的this指向

一般指向**调用函数的对象**，如果是直接调用函数则指向**全局对象（浏览器是`window`，严格模式下是`undefined`**。如果是构造函数调用则是指向新创建的实例对象，`call`、`apply`、`bind`可以显示指定绑定的对象。



##### 2. this绑定的优先级：

new 绑定 > 显式绑定（call、apply、bind） > 隐式绑定（对象调用） > 默认绑定（指向全局对象）。



**call、apply、bind 的区别**

- `call` 会立即调用函数。第一个参数是 `this` 的指向，后面的参数是传递给函数的具体参数。
- `apply` 与 `call` 的唯一区别在于**传参方式**。它接收一个数组（或类数组对象）作为参数列表。
- `bind` 不会立即执行函数，而是创建一个**永久绑定**了 `this` 的新函数。



### 四、原型与原型链

JavaScript 的原型和原型链，本质是一种**基于对象的继承机制**。通过原型链实现属性查找和方法复用，使多个对象能够共享同一份数据和行为，同时避免重复创建，提高性能。

#### 原型

**官方定义：**当使用 `new` 调用函数时，构造函数的 `prototype` 属性将成为结果对象的原型。

对象的原型是其内部属性 `[[prototype]]`（可以通过私有属性 `.__proto__`访问），在通过 new 创建对象时这个属性就是指向构造函数的 `prototype` 属性。

而原型对象上有个 `constructor` 属性指向构造函数的 `prototype`。



**核心作用：**原型的本质作用就是**实现属性和方法的共享**。原型机制通过“引用共享”，避免了函数的重复创建，提高了内存的利用率。



#### 原型链

当访问一个对象属性时，JavaScript 引擎会先查对象本身，如果本身没有这个属性就会查它的原型，如果还没有就继续往上找直到找的 `null`，这条路径就是原型链。

原型链的终点就是 `Object.prototype`，因为绝大多数对象都是从 `Object.prototype` 继承而来的。 



##### JS 实现继承的几种方式：

1. **原型链继承**

   ```javascript
   function Parent() {
       this.name = 'parent';
   }
   Parent.prototype.say = function() {}
   function Child() {}
   Child.prototype = new Parent();
   // 此处的最优解其实是：
   // Child.prototype = Object.creat(Parent.prototype);
   
   const c = new Child();
   c.say(); // 能够访问到
   ```

2. 构造函数继承（详见`手撕.md`）



##### new 一个构造函数究竟干了什么：

1. 创建一个新对象
2. 将新对象的原型指向构造函数的 `prototype` 。
3. 将构造函数的 `this` 指向新对象，为其添加属性。
4. 返回新对象。
