# 垃圾回收机制（GC）

JavaScript 的垃圾回收机制是 JavaScript 引擎中非常核心的一部分，负责自动管理内存的分配和释放。

#### 可达性

JavaScript 垃圾回收的基准概念是可达性。“可达”的值就是那些可以通过某种方式访问或可用的值，它们会被保留在内存中。

1. 固有的可达值
   - 全局变量（如 window、global）
   - 当前执行上下文及其局部变量和参数
   - 嵌套调用链上其他函数的变量和参数
2. 其他可达值
   - 如果一个值可以通过引用或引用链从“根“访问到，那么它就被认为是可达的。

垃圾回收器的工作原理就是定期找出那些“不可达”的对象，并释放它们占用的内存。



#### 垃圾回收算法

历史上 JavaScript 引擎使用过两种垃圾回收算法：**引用计数垃圾回收**、**标记清除算法**。现代 JavaScript 引擎不再使用引用计数进行垃圾回收。

##### 引用计数垃圾回收

这是最初级的垃圾回收算法。此算法把确定对象是否仍然需要这个问题简化为确定对象是否仍有其他引用它的对象。如果没有指向该对象的引用，那么该对象称作“垃圾”或者可回收的。

- **规则：**当声明了一个变量并将一个引用类型值赋给变量时这个值的引用次数就为 1，如果同一个值又被赋给另一个变量那么引用次数又加一；反之，如果包含对这个值的引用的变量又取得了另外一个值，引用次数减 1。当引用次数为 0 时说明没有办法再访问这个值了，可以回收内存。

这个回收算法有一个致命缺点就是当两个对象互相引用时即使这两个对象都已经不再被程序的其他地方使用，它们的引用次数也是 1，永远不会被回收，从而导致内存泄漏。



##### 标记清除算法

现代浏览器都采用这个方法以解决循环引用的问题。

- 步骤：
  - **标记：**垃圾回收器从“根”开始，开始遍历所有引用的对象，把能遍历到的对象打上标记
  - **清除：**遍历堆内存中的所有对象，将没有打上标记的对象清除掉，释放内存。



#### 现代 V8 引擎的垃圾回收机制

每次垃圾回收都要遍历所有对象，会导致 JavaScript 线程暂停运行，引起页面卡顿。

V8 引擎基于分代假说进行了优化，将堆内存分为了**新生代**和**老生代**，分别使用不同的回收算法：

- **新生代（Scavenge 清除算法）**
  - 新生代内存被一分为二，成为 From 空间和 To 空间。
    1. 新分配的对象被放在 From 空间内
    2. 当 From 空间快满时就触发回收机制
    3. GC 会扫描 From 空间，把可达的对象复制到 To 空间，并且紧凑地排列起来。
    4. 清空 From 空间
    5. 将 From 和 To 角色互换
  - **对象晋升：**如果一个对象在新生代中经历了多次 Scavenge 后仍存活，或者 To 空间的占用比超过了 25%，就移动到老生代。
- **老生代（标记清除和标记整理）**
  - 标记清除：即上面的标记清除算法，标记活对象清除死对象。但直接清除会产生大量的内存碎片。
  - 标记整理：为了解决内存碎片问题，V8 会在清除不可达对象后将所有的存活对象向内存的一端移动，然后直接清理掉边界之外的内存。
