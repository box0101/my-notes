# 事件循环

[学习参考MDN](https://mdn.org.cn/en-US/docs/Web/JavaScript/Event_loop)

**官方定义**

事件循环是 JavaScript 默认使用单线程前提下，Node.js能够执行非阻塞I/O操作的关键。这是Node.js官方对于事件循环的解释，那么在浏览器（HTML）层面，事件循环则是用于调度浏览器中JavaScript的**异步任务**，同时兼顾**UI渲染**。



##### 为什么 JavaScript 是单线程

JavaScript 的主要用途是与用户交互以及操作 DOM，如果是多线程的会出现同时操作同一个 DOM 等并发冲突，如果引入锁机制和线程同步，就会极大增加编程复杂和性能损耗，要处理死锁等情况。单线程能确保对 DOM 的操作是**原子性**且**串行**的，避免了复杂的线程同步问题，保证了 UI 的一致性和稳定性。

[^原子性]: 一个操作要么完全执行完要么完全不执行。



#### 浏览器的事件循环

**异步执行的运行机制：**

1. 所有同步任务都在主线程上执行，形成一个执行栈。
2. 主线程之外还存在一个“任务队列”，只要异步任务有了运行结果就在任务队列中放置一个事件。
3. 一旦执行栈的同步任务全部执行完毕，系统就会读取任务队列。对应的异步任务则结束等待状态进入执行栈开始执行。
4. 主线程不断重复上面三步。

主线程从任务队列中读取事件，这个过程是循环不断的，所以整个这种运行机制又称为**事件循环(Event Loop)**。

值得注意的是，任务其实就只有微任务和宏任务两种，同步代码并不是一种任务，而是当前正在执行的代码，而宏任务和微任务本质上都是待执行的回调函数。

Event Loop 每一轮会从宏任务队列中取出一个宏任务压入执行栈中执行（代码最开始 script 就是一个宏任务），其中会产生微任务就压入微任务队列，产生新的宏任务就压入宏任务队列，执行完当前宏任务后会清空微任务队列，将其中的回调函数逐个取出并执行，当微任务全部执行完毕后浏览器可能会进行 DOM 渲染，接着会进入下一轮循环。



**宏任务和微任务：**

任务队列不止一种，根据任务种类不同可以分为微任务和宏任务。常见任务如下：

- 宏任务：`script`、`setTimeout`、`setInterval`、`setImmediate`
- 微任务：`Promise`、`process.nextTick`
- `requestAnimationFrame` (简称 rAF) 既不属于宏任务，也不属于微任务，这是浏览器渲染阶段的一个钩子，是由**浏览器渲染引擎**发起的任务，旨在让开发者在下一次重绘前有机会修改 DOM 或样式，从而保证动画的流畅度。

EventLoop在处理宏任务和微任务的执行机制：

1. JavaScript引擎首先取出第一个宏任务
2. 执行完毕后再从微任务队列中将所有任务取出并按顺序全部执行，如果这一过程中产生新的微任务也要执行。
3. 然后再从宏任务队列中取下一个，执行完毕后再将微任务队列的任务全部取出，循环往复。

也是就是说，一次 Eventloop 循环会处理一个宏任务和所有这次循环中产生的微任务。

**二者区别：**

- 宏任务会交由另一个线程执行，例如setTimeout会交由定时器执行完毕后再放入队列等待执行回调函数。
- 微任务不需要特定的异步线程去执行，没有明确的异步任务去执行，只有回调。

**为什么要区分宏任务和微任务：**

区分宏任务和微任务，主要是为了区分任务优先级。微任务会在当前宏任务执行结束后立即执行，从而保证某些关键逻辑（如 Promise 回调）能够尽快执行，保证执行顺序的可预测性和程序状态的一致性；而宏任务则在下一轮事件循环中执行，用于处理定时器、I/O 等任务。



**为什么 `nextTick` 是微任务：**

为了让回调在 DOM 更新之后、下一轮之前立刻执行。

`nextTick` 的作用是在 DOM 更新完后执行一段回调逻辑。当宏任务里的同步代码执行完后会将 DOM 更新任务放入微任务，而 `nextTick` 放在微任务的最末尾，能够保证在 DOM 更新后，下一轮循环开始前就执行回调。



#### Node.js的事件循环

事件循环分为若干个阶段，每个阶段都有一个先进先出的回调队列需要执行，当队列耗尽或达到回调限制时再移动到下一个阶段。

**阶段概述**

- 定时器timers：执行由 `setTimeout()` 和 `setInterval()` 调度的回调。
- 待定回调pending callbacks：执行延迟到下一个循环迭代的I/O回调。
- idle, prepare（空闲、准备）：仅供内部使用。
- poll（轮询）：检索新的 I/O 事件；执行与 I/O 相关的回调（几乎所有回调，除了关闭回调、定时器调度的回调和 `setImmediate()`）；在适当的时候，Node 会在此处阻塞。
- check（检查）：`setImmediate()` 回调在此处被调用。
- close callbacks（关闭回调）：一些关闭回调，例如 `socket.on('close', ...)`。



#### `$nextTick`原理及作用

**作用：**

等待下一次DOM更新刷新的工具方法。让回调函数在DOM更新后再执行。

**底层原理：**

`nextTick()`会将回调函数放入`callbacks`队列中或者`Promise.then`，当Vue执行完当前同步任务及宏任务后事件循环进入微任务阶段，Vue会先flush更新队列（patch DOM/更新组件），然后再执行`callbacks`中的函数或`Promise.then`，因此回调看到的就是更新后的状态。
