# 项目打包

1. **新建入口文件 `src/index.ts`**

   入口文件主要三个职责：

   （1）**统一导出：**完成了两种导出方式，具名导出和默认导出，具名导出允许用户按需引入，默认导出则导出了一个包含`install`方法的对象，是为了支持`app.use()`的全局全量注册。

   （2）**批量注册：**在install函数内部维护了一个组件数组，通过遍历数组调用`app.component()`自动注册所有UI组件。

   （3）**CDN兼容：**在了一段判断window的逻辑，如果是通过`<script>`标签直接引用的会自动检测Vue并进行安装，方便传统项目使用。

2. **配置`vite.config.ts`**

   （1）**开启库模式：**在`build`配置中使用了`lib`选项开启`Vite`的库模式。指定了入口、样式（ESM和UMD两种格式），还设置了变量名。

   （2）**排除依赖：**同样在`build`配置中，使用`rollupOptions`选项把`vue`排除，否则打包的文件会包含一份完整的Vue源码。

   （3）**工程化插件配置：**配置了`VueMacros`（增强了 Vue 的开发体验）、`vite-plugin-vue-jsx`、 `eslint` （保证构建时的代码规范）。

   [^ESLint]: 是一个静态代码分析工具，在项目中用于检查TS类型错误和潜在逻辑Bug，还有强制执行Vue的最佳实践（比如组件名必须多单词）。

3. **配置`tsconfig.json`**

   配置 TypeScript 相关规则，配置 paths 支持 @ 代替 `./src`，配置`"noImplicitAny": false`规定代码必须显式写类型。

4. **配置** **`package.json`**

   项目元数据和脚本命令：

   ```json
   {
   
       "type": "module",           // 使用 ES Module
   
       "files": ["dist", "README.md"],   // npm 发布包含的文件
   
       "scripts": {
   
       "build": "run-p type-check build-only",  // 并行执行类型检查和构建
   
       "build-only": "vite build",       // Vite 构建
   
       "type-check": "vue-tsc --noEmit"     // 类型检查
   
       }
   
   }
   ```

   

**配置文件作用总结**

| 配置文件 | 作用 | 如果不配置会怎样 |
|---------|------|----------------|
| `src/index.ts` | 统一导出入口 | 用户无法引入组件 |
| `vite.config.ts` | 打包规则 | 打包成网页，不是库 |
| `tsconfig.json` | TS 编译规则 | 类型报错、路径别名失效 |
| `package.json` | 项目元数据 | 无法发布到 `npm` |
| `postcss.config.cjs` | CSS 处理 | 高级 CSS 语法不支持 |



## 组件库按需引入

按需引入主要通过以下三个层面来实现：

**第一，目录与模块结构设计（物理按需）：**
我们将组件库的每个组件拆分为独立的 `.vue` 文件，存放在 `src/components/` 目录下。这种‘单文件、独立导出’的结构，从源码层面保证了每一个组件都是一个独立的模块，为按需加载奠定了基础。

**第二，基于 Vite 的库模式构建（构建按需）：**
我们使用 Vite 的 Library Mode 将项目打包。通过在 `vite.config.ts` 中配置 `build.lib`，将项目编译为 **ES Modules (ESM)** 格式。

- **Tree Shaking 的支持**：得益于 ESM 静态编译的特性，当用户以 `import { Button } from 'clt-element'` 的方式引入时，打包工具（如 Webpack 或 Vite）在进行打包优化时，可以通过静态分析识别出哪些组件被真正使用了，从而自动剔除未引用的组件代码，减小用户最终的打包体积。

**第三，灵活的引入方式（开发按需）：**
为了方便用户，我们提供了两种引入模式：

1. **具名导出（Named Import）**：用户通过 `import { Button } from 'clt-element'` 引入，配合打包工具的 Tree Shaking 实现自动按需。
2. **路径直引（Direct Import）**：用户也可以通过 `import Button from 'clt-element/dist/components/button/Button.vue'` 直接指定具体的组件文件路径。这种方式绕过了全局入口，直接定位到文件，在构建时可以确保只加载该特定组件及其相关的依赖，从而实现更直接的按需引入。
