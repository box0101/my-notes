# 用户行为埋点系统技术文档

## 一、系统架构概览

本项目实现了一套完整的用户行为埋点系统，主要包含以下核心模块：

- **心跳机制**：基于时间差补偿的智能定时器
- **可见性API监听**：页面状态变化监控
- **埋点上报**：用户行为数据收集与上报
- **访客识别**：唯一用户标识管理

## 二、核心实现细节

### 2.1 心跳机制实现

**文件位置：** `packages/dw-tools/src/hooks/useHeartBeat.ts`

#### 关键技术点：
```typescript
// 第12-16行：核心状态管理
let timer: number | null = null;
let isActive = false;
let isStopped = false;
let startTime: number = 0;
let remainingTime: number = duration;
```

**时间差补偿算法：**
```typescript
// 第54-70行：暂停机制
const pause = () => {
  if (!isActive || isStopped) return;

  // 计算当前周期已过去的时间
  const elapsedTime = Date.now() - startTime;
  // 计算剩余时间
  remainingTime = duration - elapsedTime;

  // 如果已超时，重置为完整周期
  if (remainingTime < 0) {
    remainingTime = duration;
  }

  clearTimer();
  isActive = false;
};
```

**恢复机制：**
```typescript
// 第72-87行：恢复机制
const resume = () => {
  if (isActive || isStopped) return;
  isActive = true;

  // 先用setTimeout完成剩余时间
  timer = window.setTimeout(() => {
    callback();
    // 剩余时间执行完后，启动正常的定时器
    startTime = Date.now();
    timer = window.setInterval(() => {
      callback();
      startTime = Date.now();
    }, duration);
  }, remainingTime);
};
```

#### 面试拷打要点：
1. **为什么需要时间差补偿？**
   - 避免页面不可见时定时器继续执行导致的数据不准确
   - 确保恢复后能精确继续剩余时间，而不是重新开始完整周期

2. **如何避免内存泄漏？**
   - 在组件卸载时调用 `stop()` 清理定时器（第132-140行）
   - 移除所有事件监听器

const handleVisibilityChange = () => {

   - `blur/focus`：处理窗口切换场景

2. **不同浏览器的兼容性处理？**

#### 核心实现：
```typescript
// 第177-201行：trackEvent函数
export async function trackEvent(eventName: string, eventData?: Record<string, any>, router?: Router) {
  try {
    const authStore = (await import('@/stores')).useAuthStore();
    
    // 自动生成访客ID（第180-182行）
    if (!authStore.visitorId) {
      authStore.visitorId = uuidv4();
    }
    
    // 收集上下文信息（第183-185行）
    const path = router?.currentRoute.value.path;
    const routeName = router?.currentRoute.value.name || '';
    const from = router?.currentRoute.value.query.from;
    
    // 上报数据（第186-197行）
    void monitorApi({
      log: JSON.stringify({
        name: eventName, // PC端直接使用事件名
        name: 'm-' + eventName, // 移动端添加前缀
        userId: authStore.userId || undefined,
        visitorId: authStore.visitorId,
        timestamp: new Date().toISOString(),
        path,
        routeName,
        from,
        ...eventData,
      }),
    });
  } catch (error) {
    console.error('failed to track event:', error);
  }
}
```

**监控API实现：**
```typescript
// 文件位置：apps/homepage/src/apis/monitor.ts（第27-29行）

  return await monitorClient.post('/api/monitor', data);

```
